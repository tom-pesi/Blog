6 - 说一下 Web 安全攻击及防范措施 ​

随着互联网的普及和技术的不断发展，Web 应用面临的安全威胁也越来越复杂。每一个 Web 开发者都应该意识到 Web 安全的重要性，因为一个小小的漏洞就可能导致整个系统的崩溃，甚至数据泄露和金钱损失。本文将详细介绍几种常见的 Web 安全攻击方式及其防范方法，帮助开发者在开发和运维过程中提高 Web 应用的安全性。

1. XSS（跨站脚本攻击） ​

攻击流程： ​

  1. 攻击者在 Web 应用中找到一个允许用户输入内容（如评论、搜索框等）的表单。
  2. 攻击者在这些表单中输入恶意的 JavaScript 代码（例如 <script>alert('XSS')</script>）。
  3. 当受害用户浏览该页面时，服务器没有对输入进行正确处理，恶意的 JavaScript 代码就会被执行。
  4. 恶意脚本可能会执行窃取用户的 Cookie 信息、篡改页面内容，或重定向用户到恶意网站。

防范方法： ​

  • 输入验证和输出转义：对所有用户输入进行严格的验证，禁止输入 HTML 标签和 JavaScript 代码。输出时对特殊字符（如 <、>、& 等）进行转义，防止脚本执行。
  • 内容安全策略（CSP）：通过 CSP 限制网页中可执行的脚本来源，从而减少 XSS 攻击的风险。
  • HTTPOnly 和 Secure Cookie：将 Cookie 的 HTTPOnly 属性设置为 true，防止 JavaScript 访问 Cookie，Secure 属性可以确保 Cookie 仅通过 HTTPS 协议传输。

2. SQL 注入（SQL Injection） ​

攻击流程： ​

  1. 攻击者在 Web 应用的输入字段（如登录表单、搜索框）中插入恶意的 SQL 语句，例如：' OR 1=1 --。
  2. 如果应用未对用户输入进行过滤或转义，这些恶意输入会被直接拼接到 SQL 查询中，导致 SQL 查询的结构被篡改。
  3. 攻击者可以通过这样的输入来绕过身份验证、访问、修改或删除数据库中的敏感数据。
  4. 在某些情况下，攻击者甚至可以通过 SQL 注入执行系统命令，获取对服务器的完全控制。

防范方法： ​

  • 参数化查询：使用参数化查询或预处理语句来执行 SQL 查询，避免直接拼接用户输入到 SQL 语句中，从而避免 SQL 注入漏洞。
  • 输入验证：对所有用户输入的数据进行严格的验证，禁止恶意字符（如单引号 '、双引号 " 等）出现在输入中。
  • 最小化数据库权限：限制数据库账户的权限，确保应用程序只有执行必要的操作权限，防止攻击者获得过高权限。

3. CSRF（跨站请求伪造） ​

攻击流程： ​

  1. 攻击者知道用户已登录某个网站并保存了有效的身份认证信息（如 Cookie）。
  2. 攻击者诱导用户访问一个恶意网站，或发送包含伪造请求的链接。
  3. 用户在访问恶意网站时，浏览器自动携带用户的认证 Cookie 向目标网站发送请求。
  4. 由于目标网站信任用户的身份，伪造请求就会被执行，可能导致用户执行不该执行的操作（如转账、修改账户设置等）。

防范方法： ​

  • CSRF Token：每次请求时，生成一个唯一的 CSRF Token，并将其添加到请求中（如表单中），然后服务器验证该 Token 是否正确，防止伪造请求。
  • SameSite Cookie：使用 SameSite 属性设置 Cookie，确保 Cookie 只在同一站点下发送，防止跨站请求携带 Cookie。
  • Referer 和 Origin 验证：检查请求头部的 Referer 或 Origin 字段，确保请求来源可信。

4. 点击劫持（Clickjacking） ​

攻击流程： ​

  1. 攻击者将受害者网站的页面嵌套在自己的网站中（通常使用 iframe 标签）。
  2. 攻击者通过 CSS 或 JavaScript 将嵌入的页面隐藏或遮挡住，可能覆盖一个按钮或表单。
  3. 用户在浏览攻击者网站时，看到的是攻击者精心设计的页面，误以为自己正在点击攻击者提供的按钮或链接。
  4. 用户实际上是在点击隐藏在页面下的受害者网站的按钮，执行了不该执行的操作（如提交表单、转账等）。

防范方法： ​

  • X-Frame-Options：通过设置 HTTP 头部 X-Frame-Options: DENY 或 X-Frame-Options: SAMEORIGIN，防止页面被嵌套在 <iframe> 中。
  • Content Security Policy（CSP）：使用 CSP 设置 frame-ancestors 指令，明确允许哪些来源的网站嵌入页面，进一步防止点击劫持。

5. 暴力破解（Brute Force Attack） ​

攻击流程： ​

  1. 攻击者通过自动化工具不断尝试不同的密码组合，进行暴力破解。
  2. 攻击者尝试登录页面，输入用户名和一个密码组合，并验证是否成功。
  3. 如果密码错误，攻击者继续使用不同的密码进行尝试，直到猜对正确的密码。
  4. 如果攻击者成功获取账户的密码，他就可以登录并获取受害者的敏感信息。

防范方法： ​

  • 账户锁定机制：对连续多次失败的登录请求进行限制，暂时锁定账户或要求进行验证码验证。
  • 强密码策略：要求用户使用包含字母、数字和特殊字符的强密码，避免使用简单的密码。
  • 多因素认证（MFA）：启用多因素认证，即使攻击者破解了密码，也无法访问账户。

6. 中间人攻击（MITM） ​

攻击流程： ​

  1. 攻击者通过监听网络流量，拦截用户和服务器之间的通信。
  2. 攻击者在通信过程中充当中间人，可能修改或窃取传输的数据（如用户的用户名、密码或信用卡号）。
  3. 攻击者也可以伪造消息，向用户或服务器发送恶意命令。
  4. 用户或服务器未意识到数据已经被篡改，导致信息泄露或系统遭到攻击。

防范方法： ​

  • 使用 HTTPS：确保所有敏感数据（如密码、银行卡信息等）都通过 HTTPS 进行加密传输，防止数据被窃取。
  • SSL/TLS 验证：使用有效的 SSL/TLS 证书，验证网站的身份，防止攻击者冒充合法网站。
  • HSTS（HTTP Strict Transport Security）：启用 HSTS，强制浏览器仅通过 HTTPS 协议访问网站，防止被劫持到 HTTP 协议。

7. 文件上传漏洞（File Upload Vulnerabilities） ​

攻击流程： ​

  1. 攻击者通过 Web 应用的文件上传功能上传恶意文件（如 Web Shell 或可执行文件）。
  2. 攻击者通过上传的文件来执行恶意代码，利用服务器的漏洞获取控制权。
  3. 如果文件存储在可以直接访问的目录中，攻击者可能通过 URL 直接访问该文件。
  4. 文件执行后，攻击者可以控制服务器，进行进一步的攻击。

防范方法： ​

  • 限制上传文件类型：只允许上传特定类型的文件（如图像、文档等），禁止执行脚本文件（如 .php、.exe 等）。
  • 文件内容检测：对上传的文件进行病毒扫描、文件类型检查和安全性检测。
  • 存储目录安全：将上传文件存储在无法直接访问的目录中，并为上传文件重新命名，防止恶意文件被直接执行。

8. Session 劫持（Session Hijacking） ​

攻击流程： ​

  1. 攻击者通过网络监听获取合法用户的会话 Cookie。
  2. 攻击者将会话 Cookie 伪造为自己的，会话状态变为用户身份。
  3. 攻击者通过伪造的 Cookie 提供的身份信息，执行未授权的操作（如修改账户信息、转账等）。
  4. 用户可能未意识到自己账户的安全已经受到威胁。

防范方法： ​

  • 使用 HTTPS：确保会话标识（如 Cookie）

在传输过程中加密，防止被窃取。

  • 设置 HTTPOnly 和 Secure 标志：将 Cookie 设置为 HTTPOnly，防止 JavaScript 访问；并设置 Secure，确保 Cookie 只通过 HTTPS 协议传输。
  • 会话过期：设置会话的过期时间，定期更新会话 ID，防止长期有效的会话被盗用。

9. 路径遍历（Directory Traversal） ​

攻击流程： ​

  1. 攻击者通过修改文件路径（例如：../../etc/passwd）来访问本不该访问的文件。
  2. 如果应用没有对路径进行适当的验证，攻击者可能绕过文件系统的安全控制，读取敏感文件。
  3. 攻击者可能获取系统配置文件、数据库文件或用户凭证等敏感信息。

防范方法： ​

  • 输入验证：严格验证用户输入的文件路径，避免出现 ../ 等路径穿越字符。
  • 限制文件访问：限制应用能够访问的目录范围，确保用户不能访问应用外的文件。
  • 文件存储隔离：将用户上传的文件存储在安全的目录中，避免被直接访问。

10. DoS 和 DDoS 攻击 ​

攻击流程： ​

  1. 攻击者向目标 Web 应用发送大量无意义的请求，目的是消耗服务器的计算资源或带宽。
  2. 在分布式拒绝服务攻击（DDoS）中，攻击者通过大量的受感染的设备（如僵尸网络）同时发起攻击。
  3. 服务器因大量请求无法处理合法用户的请求，导致服务不可用。

防范方法： ​

  • 流量监控与限制：通过流量监控系统检测和限制异常流量，避免服务器过载。
  • CDN 和负载均衡：使用内容分发网络（CDN）和负载均衡技术，分散和控制流量。
  • 防火墙和抗 DDoS 服务：部署 Web 应用防火墙（WAF）和专门的 DDoS 防护服务，提前检测和拦截攻击。

11. 总结 ​

Web 应用面临的安全威胁多种多样，包括 XSS、SQL 注入、CSRF、点击劫持等。每一种攻击方式都有其独特的攻击流程，但通过合理的防范措施，开发者可以有效地降低这些攻击的风险。 Web 安全是开发过程中的重要环节，了解常见的攻击方式并采取防范措施，能够有效保护用户数据和系统的稳定运行。
